# 小规模非规范水果数据实验

数据位置：`route2/local_data/fruit_probe_10k`。独立核对文件位置：`route2/local_data/fruit_probe_10k_evaluation`。生成器默认生成 10,000 行，随机种子为 20261016；原来的百万行数据保留。

2026-10-17 已生成并校验：23 张表、519 列、10,000 行，输入文件共 2,176,397 字节，约 2.2 MB。原数据 1,102,238 行，新数据约为其 0.91%。其中 API 80 行、Card 60 行、入参 900 行、出参 1,100 行、参数引用 3,500 行、指标 120 行、度量 80 行，另有 1,200 行多层成员及其他辅助表。

404 列的注释为空或重复列名，占 77.8%；46 列同时含 JSON 形态与其他值，24 列同时含数字与非数字形态。这些比例是生成结果，不是对生产数据的统计。

数据校验和 12 项新增测试通过。当前代码的真实导入及全列画像耗时约 5.06 秒，读取全部 10,000 行，未读取核对答案作为数据源。报告见 `fruit_probe_10k_evaluation/import_report.json`，测试日志见同目录的 `fixture_tests.log`。未启动模型实验，模型调用为 0。

这套数据用于定位缺失注释、编码碰撞、混合格式和不完整关联导致的抽取问题。它依据已讨论的问题构造，未使用真实 IOC 数据；异常比例是实验设定，不代表生产环境的真实分布。

API 和 Card 分别有自己的输入输出参数，没有预设 Card 调用 API。组织成员有多级父子关系。重复编码需要结合租户、维度及来源范围解释，不能仅靠值相同连边。数据保留可识别的正常记录，同时包含缺失引用、混合中文/编码/JSON、缺少判别信息等情况。

输入描述中不写“这是可复用度量定义”等本体分类答案。业务名称、计算公式、单位等普通源信息仍保留。不要把信息全部删掉后，再要求模型恢复无法从输入判断的事实。

核对文件与输入目录分开。`oracle.json` 记录应有关系、不得接受的错误关系、证据不足的案例及有意引入的异常。它只用于评价，不得放入抽取配置、提示词或模型上下文。核对文件里的类别是生成器的测试标签，不是抽取系统已经识别出的结果。

当前核对文件包含 19,448 条正向关系见证、82 条禁止关系、63 个歧义案例及 22 个异常记录。它覆盖资源归属、参数引用、指标属性和成员层级；辅助来源、地区背景、宽表背景及继承的描述 JSON 没有穷举关系答案。未列举的关系不能直接判错。

在 `route2` 目录下重新生成其他规模的数据：

```bash
.venv/bin/python scripts/generate_fruit_probe_data.py generate \
  --output local_data/fruit_probe_3k --rows 3000 --seed 20261016
```

生成器拒绝覆盖已有目录。相同参数生成相同输入；默认另建同级的 `fruit_probe_3k_evaluation` 目录。改变规模后应重新生成关联和核对文件，不要分别截取各表前若干行，否则会制造额外的断链。

校验已生成的数据：

```bash
.venv/bin/python scripts/generate_fruit_probe_data.py validate \
  --input local_data/fruit_probe_10k
```

用当前项目的真实导入和画像模块检查数据：

```bash
.venv/bin/python scripts/inspect_fruit_probe_data.py \
  --input local_data/fruit_probe_10k
```

检查结果写入核对目录的 `import_report.json`，包含逐表行数、逐列完整统计、输入摘要及代码摘要。它不加载 `.env`，不初始化模型。重复检查时用 `--report` 指定新文件，已有报告不会被覆盖。

按用户要求，正式启动前先提醒用户在本地配置 API key，收到配置完成的确认后再运行。模型配置位于 `route2/.env`，需要 `ONTOLOGY_LLM_MODEL`、`ONTOLOGY_LLM_BASE_URL`、`ONTOLOGY_LLM_API_KEY`；不要把 key 写进数据、核对文件或聊天。

未来启动小规模模型实验时，使用 `config/runtime.fruit-probe.yaml`。该配置指向新数据，最多 128 次模型调用、并发 1，保留审核，关闭业务事实抽取、类型泛化和多轮修复。审核和重试也消耗预算，128 次不保证覆盖全部证据包。先串行便于区分数据问题与并发问题。它不会读取独立核对文件。

```bash
PYTHONPATH=code .venv/bin/python -m ontology_r2.cli build \
  --config config/runtime.fruit-probe.yaml \
  --output runs/fruit-probe-first
```

这条命令会按项目现有模型设置调用模型。本轮数据准备不执行它。输出目录必须是新目录，其他规模需显式修改 dataset 或使用 `--dataset`。

验收时分开记录三个结果：

1. 数据校验：行数、表结构、异常清单和关系核对文件是否一致。
2. 工程执行：导入、画像、组包、抽取分别耗时多少，是否触及调用或候选上限。
3. 语义效果：正常关系是否找到，跨租户或跨对象类型的错边是否出现，证据不足的情况是否保留未决。

配置对候选和证据包有上限，因此本轮实验可能显示 `partial`。预算内未处理、规则拒绝和语义判断错误应分别统计。导入通过、测试通过或输出了图，都不能替代第三项验收。

# 轻量知识图谱：用户故事与验收标准

状态：改造设计，尚未实现或验收。本文把客户需求转成开发任务；现有项目是否已具备相应能力，以代码核查和测试结果为准。

## 范围与约束

客户输入有两条通道，允许同时使用：

1. 结构化数据：Gauss 系列数据库的完整元数据和按需读取的实例数据，或客户上传的 Excel。具体 Gauss 产品、版本、兼容模式和驱动尚未确定。
2. 知识文档：Markdown 等文档。数据说明文档帮助理解表和列；分析知识文档可以产出分析概念、方法和适用条件。

数据库返回行、样本、原始投影、包含这些内容的组包和完整 prompt 均不得持久化。不能以逐行指纹表、调试文件、日志或中间 DuckDB 文件变相保留这些数据。允许保存真正抽取出的实体、关系、属性、数据说明，以及不含原始返回值的规则状态、逻辑游标和统计计数。抽取结果保存到客户指定的位置。

Excel 上传原文件属于客户提供的输入资产，按上传资产策略管理；解析后的中间表不额外落盘。规则中需要引用的业务常量，必须作为已接受的语义映射、判别值含义或图谱属性保存，不能复制探索样本形成隐藏缓存。

以下验收使用人工构造的数据。正常退出、输出了图文件、SQL 能运行，都不能单独证明图谱正确。

## 用户故事

### US-01：接收结构化数据和知识文档两条输入

**作为构图用户**，我希望提交数据库或 Excel，并附带 Markdown 等知识文档，使结构信息、实例数据和业务说明共同参与构图。

- **Given** 同一任务包含一个数据库连接、一份 Excel、两份 Markdown，文档分别用于数据说明和分析知识。
- **When** 系统登记输入并检查访问能力。
- **Then** 每项输入有独立来源标识、版本和用途；表结构与实例读取接口分开；文档用途可以修订。没有文档时可执行结构抽取，并明确说明缺少业务说明。
- **Then** 文档用途不明确时可提出分类建议并保留不确定状态；不能默认把所有段落既当解释依据，又当已经成立的业务事实。
- **Then** Excel 保留原始列名、工作表位置及类型推断结果；解析产生的临时表仅在内存中使用，不产生持久化副本。

### US-02：确认 Gauss 实际能力并选择适配器

**作为部署人员**，我希望系统识别具体 Gauss 环境，避免把某个 PostgreSQL 或 openGauss 行为直接假定为所有 Gauss 产品都支持。

- **Given** 客户仅提供“Gauss 数据库”，尚未确认产品、版本和兼容模式。
- **When** 执行受控连接检查和能力探测。
- **Then** 报告产品、版本、驱动及已验证的只读事务、元数据读取、一致性读取、查询取消、超时、参数绑定和必要 SQL 功能；未知项保留未知。
- **Then** 只选择通过契约测试的适配器；不支持的 SQL 操作给出原因，不能自动退回字符串拼接或放宽 SQL 检查。
- **Then** 无法建立必要的只读保护时不开始实例探查。能力探测不创建表、视图或其他源库对象。

### US-03：只执行受控的只读数据库操作

**作为数据管理员**，我希望探索智能体和规则执行器都不能修改源库或绕过访问范围。

- **Given** 使用最小权限账号，配置允许访问的库、schema、表、列和函数。
- **When** 规则或智能体请求查询。
- **Then** 请求必须通过方言匹配的语法树校验、对象权限检查、函数白名单和参数绑定，并在数据库支持的只读执行环境中运行；连接控制语句由适配器固定生成。
- **Then** 单纯以 `SELECT` 开头不能放行。测试须拒绝多语句、可写 CTE、`SELECT INTO`、导出文件、锁定读取、任意函数调用，以及方言中具有副作用的查询形式。
- **Then** 不允许访问未授权表或列；设置超时、返回行数和字节数上限。超限后取消源库查询，不把结果截断后当作完整结果。
- **Then** 图谱结果库使用独立的写入接口和凭证；源库只读凭证不能承担结果写入。

### US-04：数据库返回内容不落盘

**作为数据管理员**，我希望数据库只按需返回数据，程序不保存这些返回内容。

- **Given** 样本中植入只用于测试的唯一标记，任务可能成功、报错或被中断。
- **When** 分别执行探查、LLM 判断、规则编译和批量抽取。
- **Then** 输出目录、临时目录、数据库文件、日志、追踪记录、异常附件、请求缓存和检查点中都不能出现该原始样本或完整 prompt；SDK 请求正文记录和临时文件溢写须禁用。
- **Then** 内存达到上限时任务应减小批次或停止，不能自动将返回行写入临时文件。来源数据只能进入配置允许的模型处理环境。
- **Then** 允许保存的实体属性和关系必须经过抽取与验证，并符合输出 schema；不能把整行、原始 SQL 结果或通用 JSON 包装成“证据节点”保存。
- **Then** 不建立原始投影逐行指纹表。可保存的摘要只针对已接受的图事实和规则版本；来源引用记录逻辑来源、规则和分区，不附带整行快照。

### US-05：根据构图目的选择分析范围

**作为经营分析人员**，我希望只抽取指标、度量、维度及相关知识，避免把全部经营观测值变成图节点。

- **Given** 一张宽表含组织、产品、指标编码、期间、金额和导入日志字段。
- **When** 任务目标选择定义、成员及其关系，不包含观测值图谱。
- **Then** 抽取计划列出目标实体、所需关键列、判别列、必要上下文列和排除列，并说明用途；金额记录和日志记录不逐行实例化。
- **Then** 同一来源可以在另一个明确包含观测值的任务中采用不同投影；任务目标变更必须形成新计划版本。
- **Then** 不能仅因表名含 `fact` 就忽略其中的指标定义或维度成员，也不能仅因列类型是数值就排除数值编码。

### US-06：形成可修订的数据说明

**作为数据分析人员**，我希望在抽取前知道字段的实际含义、异常和未确认事项。

- **Given** 完整元数据中有空注释、列名回声、错误说明，实例中存在中文名、编码、JSON 混存。
- **When** 系统读取元数据，并通过有界采样、画像和必要的数据库聚合探查列值。
- **Then** 数据说明分别记录声明信息、观察结论和推断假设，附验证方式及覆盖范围；样本观察不能写成全表保证。
- **Then** 名称或注释与实际值冲突时产生可定位的冲突项，保留原声明，不直接覆盖源 schema。
- **Then** 数据说明可以保存聚合结论和已接受的语义描述，不保存样本行。后续规则引用明确的数据说明版本。

### US-07：识别实体列组、属性列和非语义列

**作为构图用户**，我希望同一个对象的编码、中文名和英文名合成一个实体。

- **Given** `report_item_l2_code`、`report_item_l2_sort_column`、`report_item_l2_cn_name`、`report_item_l2_en_name`，以及实例 `(2150,112,销售费用,Selling expense)`。
- **When** 完成列组识别、编码到名称的依赖验证和语义判断。
- **Then** 形成一个实体列组，编码、名称、英文名有各自属性角色；排序值 112 不生成语义节点，可保留为来源的展示元数据。
- **Then** “指标”类型的判断须有数据说明或其他语义证据；层级结构本身只能证明这是一项层级成员，不能单独证明其为可计算指标。
- **Then** 编码对应多个冲突名称时报告冲突或限定作用范围；不能把一对一依赖作为无条件成立的假设。

### US-08：按正确的列组合去重

**作为构图用户**，我希望大量重复事实只产生有限的语义实体和关系。

- **Given** 同一组指标、组织和产品在多个期间重复出现，原始事实行数远多于语义对象数量。
- **When** 规则执行关键列投影和去重。
- **Then** 在数据库中计算所需的 `DISTINCT` 列组合或等价聚合，返回真正需要的语义组合；应用端不下载全部事实行再去重。
- **Then** 名称、编码和英文名必须来自同一条有效投影关系；不能分别取三个去重列表后作笛卡尔积。
- **Then** 仅需指标定义时不把组织、期间等无关列加入定义投影；确实要提取资源支持范围时，才单独生成相应关联投影。
- **Then** 报告区分源库扫描量、返回组合数和最终图事实数。`DISTINCT` 可能扫描源库，不承诺其成本与结果数量相同。

### US-09：从宽层级表构建实体和层级关系

**作为构图用户**，我希望将 L1～L5 列组转换成正确的成员和上下级关系。

- **Given** 同一路径中某编码从 L2 重复到 L5，另一条路径在 L4 下有两个不同的 L5 成员。
- **When** 规则展开层级列组、验证实体身份、压缩连续重复成员，再产生邻接关系。
- **Then** 重复编码且语义一致的 L2～L5 只产生一个实体，保留其来源层级信息，不生成自环；两个 L5 成员分别连接到原路径中的 L4。
- **Then** 中间空层、编码相同但名称冲突、跨分区编码碰撞、多父节点和环须分别检查；不得依据编码前缀自动补父节点。
- **Then** 用户样例中的 `2→28`、`24→2408`、`26→2608`、`261→2610` 等编码变更，没有明确映射来源就保持未确认。
- **Then** 原片段中的 `2711`、`2713` 均位于 L5 且上接 `271`；没有额外证据时不能创建 `2711→2713`。缺少表头时须先确认列组，不能把展示缩进当成源数据事实。

### US-10：发现并区分跨列关系

**作为数据分析人员**，我希望知道哪些列可以关联，以及这种关联意味着什么。

- **Given** A 表 a 列与 B 表 c 列都保存指标中文名，另有编码列、外键声明和部分重叠值。
- **When** 系统比较元数据、类型、唯一性、覆盖率、判别分区和语义说明。
- **Then** 分别记录声明外键、候选值包含、已验证引用、相同语义角色、概念映射等关系类型，并带验证状态。
- **Then** “都保存指标中文名”可以支持列角色对齐，但不能单独证明两表可直接连接、同名记录是同一指标，或存在业务上下级关系。
- **Then** 通用列名、连续整数碰撞和部分覆盖不能自动升级为确认关系；跨表查询必须有指定关联条件，禁止无条件全连接。

### US-11：用有预算的探查流程确认结构规则

**作为构图用户**，我希望系统在必要时继续查证关键结构，而不是一次采样后直接生成规则。

- **Given** 初步样本提出“L1～L5 是层级列组”或“某列是多态引用”的假设。
- **When** 探索流程选择后续操作。
- **Then** 必须形成“假设—待验证问题—受控探查—反例检查—规则状态”的记录；智能体只能申请已注册操作，不能自行执行任意 SQL 或代码。
- **Then** 预算按未确认的关键结构问题分配，并为验证保留额度；先处理实体键、层级、判别列等会影响后续批量执行的问题。
- **Then** 预算耗尽时，未验证规则标为未确认，相关范围标为未覆盖；不能因为没有发现反例就发布为已验证。
- **Then** 探索记录保存结论、方法、计数和规则状态，不保存数据库返回行或完整推理上下文。

### US-12：把规则编译成受控原子操作

**作为开发人员**，我希望一次确认的结构规则能够反复执行，而不再逐行请 LLM 解释。

- **Given** 已确认实体列组、层级列组或带判别字段的引用规则。
- **When** 编译抽取计划。
- **Then** 计划只包含受控操作，例如投影、过滤、去重、分组验证、层级展开、连续重复压缩、条件关联、实体发出、关系发出和一致性检查。
- **Then** 每个操作声明输入列、输出结构、作用范围、空值策略、验证前提和源库能力要求；解释器不能执行任意 Python、模板脚本或未经验证的 SQL。
- **Then** 相同输入语义、规则版本和配置产生稳定的逻辑结果；不同 SQL 方言由适配器负责，不由 LLM 临时改写放行。
- **Then** 不能执行的规则给出具体能力缺口，不以下载全表到本地作为默认替代。

### US-13：共用语义实体并保留来源引用

**作为构图用户**，我希望不同租户或业务数据引用同一个指标时，只看到一个语义对象。

- **Given** A、B 两个租户分别声明同一已确认指标，名称、单位、公式、期间和业务口径一致，但本地编号不同。
- **When** 生成实体和来源支持关系。
- **Then** 生成一个共享实体，保留两份带作用范围的引用及各自编号；租户和业务范围不直接成为共享实体的语义身份。
- **Then** 来源范围以联合记录保存，例如 `(租户A,业务X)`、`(租户B,业务Y)`；不能将两个租户和两个业务分别求并集后产生不存在的组合。
- **Then** 同名但单位、公式、期间、粒度或口径冲突时保留不同实体或待确认候选；缺少定义不能跨接两个已知冲突的定义。
- **Then** 共享实体上的别名和引用可以增加，已有实体标识保持稳定；本地编号的解析仍受来源命名空间约束。
- **Then** 名称、别名、定义等每个属性值分别记录来源支持与权限。A 提供别名 X、B 提供别名 Y 时，B 不因共享实体而看见 A 的私有 X；A 撤回后不影响 B 的 Y。

### US-14：展示表、列及其关系

**作为数据分析人员**，我希望从元数据图直接看清 A.a 与 B.c 的关联和证据状态。

- **Given** 两张表、各自字段、已确认引用和未确认的语义对齐候选。
- **When** 打开元数据图并展开表。
- **Then** 展示明确的表到列包含关系，跨表关系连接具体列；可由实体回溯到贡献它的表列及规则。
- **Then** 图例和详情区区分技术关联、语义对齐、业务关系，以及候选、已验证和冲突状态。
- **Then** 表折叠只改变展示，不丢失列级信息；同名字段不会因显示名称相同而被前端合并。

### US-15：使用数据说明文档辅助抽取

**作为数据维护人员**，我希望 Markdown 中关于表、字段和编码的解释进入对应探查的上下文。

- **Given** 一份说明组织层级编码的 Markdown，以及一份与当前表无关的业务文档。
- **When** 系统为某个列组判断或规则复核选择上下文。
- **Then** 按来源、适用表列、主题和版本选择相关章节，保留文档位置；未关联的文档不默认全部塞入组包。
- **Then** 说明文档与数据库观察冲突时保留两者及冲突状态；自动生成的数据说明不得反过来充当独立的第二份证据。
- **Then** 文档中的指令文本不能修改工具权限、放宽 SQL 限制或要求持久化样本。包含数据库样本的运行组包只在内存中使用。

### US-16：把分析知识文档接入图谱

**作为分析人员**，我希望从 Markdown 中提取分析方法、适用条件和依赖概念，并与已有指标和维度关联。

- **Given** 文档描述“收入下降时，按区域和产品分析变化”，图中已有收入指标、区域维度和产品维度。
- **When** 执行分析知识抽取与对齐。
- **Then** 可以生成分析方法及其关注概念、分组维度和适用条件，并保留文档版本与章节位置。
- **Then** “文档建议按区域分析”保存为文档主张，不能升级为源库存在某个计算公式、资源能力或真实业务事实的证明。
- **Then** 对齐不确定时保留候选，不按同名强行合并；文档变更后只更新该版本贡献的内容，其他来源仍支持的实体继续存在。
- **Then** “可能导致”“建议检查”等主张保留模态和条件，允许在出处核验后以文档主张发布；既不能改为确定事实，也不能被旧事实抽取器的推测词规则一律丢弃。

### US-17：分批执行规则并发布抽取结果

**作为运行人员**，我希望在有内存和查询预算的条件下执行规则，并区分已完成范围与待处理范围。

- **Given** 规则需要读取大量事实中的有限语义组合。
- **When** 按规则和分区流式处理源库投影。
- **Then** 客户端只保留有界批次，及时转成经过验证的实体、属性和关系；完整返回集不落盘。
- **Then** 只有符合输出 schema 的图事实可进入待发布结果区。发布记录包含规则版本、分区、完成状态及覆盖计数，原始返回行不能写入待发布区。
- **Then** 一致性读取能力、来源版本或完整读取条件不满足时，不声称获得某一时刻的完整快照。
- **Then** 进程失败后可以重新读取未完成分区并幂等执行；不能通过保存最后一批源数据来实现恢复。

### US-18：不为未变化的规则和内容重复调用 LLM

**作为运行人员**，我希望常规重跑只执行已验证规则，避免为同一语义内容重复付费。

- **Given** 来源结构、已验证规则、数据说明和知识文档版本未变，数据库没有新增语义定义。
- **When** 再次执行任务。
- **Then** 规则化实体和关系不再逐行调用 LLM；已有图事实被幂等更新，不重复创建对象或来源引用。
- **Then** 没有可靠增量信号时，可重新在数据库执行关键列 `DISTINCT`，并在内存中对照已发布图事实；明确报告本次仍发生数据库扫描。
- **Then** 不建立原始关键列组合的逐行缓存或指纹库。用于判断结果是否变化的摘要仅对应已接受的图事实和规则版本。
- **Then** 新增编码若符合已确认的编码到名称规则可直接产生实例；新值形态、冲突定义或未知判别值触发定向复核，不把所有新行送给 LLM。

### US-19：正确处理新增、修改、删除和共享引用

**作为构图用户**，我希望源数据变动后，图谱既能更新，也不会误删仍被其他来源引用的对象。

- **Given** 同一实体由两个来源分区支持，其中一份引用被删除，另一份仍有效。
- **When** 重算受影响分区并完成验证。
- **Then** 只撤回消失的支持关系；最后一个有效支持消失后，才根据输出策略撤回实体或标为失效。
- **Then** 只有可靠删除事件，或该分区完成一致、完整的规则执行，才能证明旧支持应撤回。采样、查询超时、预算耗尽和不完整分页不能作为删除证据。
- **Then** 只提供更新时间且不能识别删除的来源，必须标明“新增/修改可检测，删除未保证”；不能把这种模式标成完整增量。
- **Then** 修改关键列需要撤回旧含义并增加新含义；断点重放不造成双倍支持计数。CDC 或游标内容在运行中消费，持久状态只保存逻辑位置和已抽取事实的支持关系。
- **Then** 对节点存在、属性值/别名、关系及文档主张分别撤回支持；共享节点继续存在时，已失效的独有别名也必须消失。

### US-20：处理结构漂移、中断和不完整执行

**作为运行人员**，我希望字段变化或探查失败不会静默污染已发布图谱。

- **Given** 已发布规则依赖某个字段类型、层级列组和文档版本。
- **When** 发生字段删除、类型改变、判别值扩展、规则升级、进程中断或知识说明冲突。
- **Then** 只使受影响规则及其下游结果失效或待复核，记录明确原因；不因无关代码变更自动重做全部源库探查。
- **Then** 复核通过后按新规则版本重算相关分区，原结果在新结果完整发布前保留明确版本状态；半次失败的执行不覆盖已确认结果。
- **Then** 检查点包含逻辑任务状态，不包含源行、样本或完整组包。恢复时重新读取必要数据，并再次检查访问权限和规则前提。

### US-21：用固定样例证明结构和增量正确

**作为验收人员**，我希望用小数据证明关键行为，而不是依赖大规模运行截图。

- **Given** 下文列出的固定样例和明确真值，包含正确情况、反例和不确定情况。
- **When** 执行单元测试、适配器契约测试及小规模端到端回放。
- **Then** 逐项核对实体集合、关系集合、属性、来源支持、冲突和未覆盖范围；同名去重率和节点数量不能替代正确性验证。
- **Then** 结构化规则可完全离线测试；Gauss 实际执行必须在客户对应产品和版本通过测试，其他数据库测试通过不替代这一结果。
- **Then** 保留程序确定的测试真值，不把分类答案或“这是一个指标”之类提示写进待抽取样本，防止测试只验证答案回声。

### US-22：控制成本并解释未覆盖范围

**作为运行人员**，我希望看清数据库成本、模型成本和未完成原因，并能调整后续预算。

- **Given** 已配置查询时长、并发、返回量、内存和模型调用预算。
- **When** 任务接近或达到任一上限。
- **Then** 系统按优先级停止新探查，取消超时查询，报告已执行规则和未覆盖的表、列组或分区；不能将预算限制显示成完整成功。
- **Then** 统计分别列出元数据读取、样本探查、完整聚合、去重投影、规则执行和文档抽取的查询次数、耗时、返回规模及 LLM 调用数。
- **Then** 日志保留规则与查询模板标识、状态、计数和耗时，不记录包含源数据的 SQL 参数或响应正文。

## 固定验收样例

| 样例 | 内容 | 必须验证的结果 |
|---|---|---|
| F01 列组 | 编码、中文名、英文名、排序号；加入中文名冲突和空值 | 正确归为一个列组；排序号不建节点；冲突不被吞掉 |
| F02 宽层级 | L1～L5、连续重复编码、空层、两个同父 L5、编码碰撞 | 无自环；同父 L5 不变成父子；未确认编码变换保留未知 |
| F03 事实重复 | 相同定义在多个期间、组织和产品组合中重复 | 定义对象数量不随事实行数线性增加；组合关系来自原数据 |
| F04 共享与同名异义 | 两租户同义不同编号；另加同名不同单位或公式 | 同义共享一实体并保留两份引用；冲突定义不合并 |
| F05 跨列表达 | 同名列不同含义、不同列名相同角色、伪外键整数碰撞 | 列角色对齐、候选引用和已确认引用严格区分 |
| F06 文档 | 数据说明、分析方法、相互矛盾的两版文档、恶意工具指令 | 上下文按用途选择；主张可溯源；指令不改变工具权限 |
| F07 增量 | 原样重跑、新成员、新判别值、关键列修改、部分来源删除 | 不逐行重调 LLM；引用幂等；最后支持消失才撤回 |
| F08 不完整读取 | 查询超时、分页失败、内存超限、进程中断 | 状态为未完成；已有实体不因未读到而删除；恢复无需源数据缓存 |
| F09 SQL 安全 | 多语句、可写 CTE、SELECT 导出/建表、越权表列、危险函数 | 在源库执行前被拒；合法受控查询仍可执行 |
| F10 不落盘 | 样本唯一标记、异常响应、LLM 请求失败、临时文件溢写 | 原始标记不出现在持久介质；只有明确接受的图属性可保存 |
| F11 方言差异 | 目标 Gauss 产品与版本的关键操作；模拟不支持功能 | 适配器能力结论准确；无未经验证的兼容回退 |
| F12 规模对照 | 固定语义真值，增加重复事实量；改变语义组合数 | 分别测源库成本与返回量；新增语义组合能被发现，不能只证明压缩得少 |

## 首版完成标准

全部 P0 故事通过对应测试；完成一次实际 Gauss 环境的受控端到端验证；数据不落盘检查覆盖成功、失败和中断；共享实体、层级关系和撤回行为与固定真值一致。尚未支持的 Gauss 特性、来源增量能力和业务语义判断，必须在结果中逐项列明。

客户提供的层级片段只能作为探查用例。缺少表头、编码不一致和 L5 关系冲突未解决前，不能将用户给出的整棵期望树直接写成唯一验收真值。
